# داشبورد أكس سبيس
موقع ويب مستقل لإدارة بيانات تطبيق التجار على نفس مشروع سوبا بيس.

## الموجود
- دخول بالبريد أو رقم عراقي 11 خانة يبدأ 07، يحوّل إلى رقم@gmail.com مثل التطبيق؛ إنشاء حساب لا يمنح صلاحية إدارة تلقائيًا.
- معاينة واجهة ببيانات فارغة دون الوصول لبيانات حقيقية.
- ملخص الطلبات والأرباح الخاصة بالتجار والسحوبات والمراجعات.
- الطلبات: بحث وفلترة، تفاصيل الزبون والمنتجات، تحديث الحالات، إلغاء الطلب بمراجعة الإدارة. التسليم والرفض نهائيان مع تأكيد.
- المنتجات: أسعار ومخزون وتصنيفات وخصومات وألوان وقياسات وصور وفيديو وإخفاء وترتيب.
- أقسام وبنرات: إضافة، تعديل، ترتيب وإخفاء، رابط عند الضغط على البنر.
- التجار: ملف، طلبات وحركات مالية، تعديل البيانات والحظر/رفع الحظر ومراجعة طلبات تعديل البيانات.
- سحوبات: مراجعة ورفض أو تسجيل تسديد بعد التحويل الفعلي، وإيصال خاص.
- دعم: محادثات مرتبطة بالطلبات ورسائل ومرفقات خاصة، فتح وإغلاق وتحديث الرسائل مع الحفاظ على مسودة الرد.
- استبدال وإحالات ومراجعة طلبات استرجاع الحساب (لا تغير كلمة السر).
- إشعارات محفوظة وإعدادات رسوم التوصيل والتوصيل المجاني والرابط المنشور للحجز.
- سجل أعمال الإدارة يتضمن تغييرات المنتجات والأقسام والبنرات والإعدادات.

## الإعداد الفعلي
طُبقت 001_x_space.sql و003_dashboard.sql على مشروع [project-ref]. تأكيد البريد مطفّي، الهاتف Disabled. فُحصت 23 جدولًا محميًا بـRLS. لم تُضف حسابات إدارة بعد ولم تُرفع بيانات المنتجات التجريبية. لا يوجد service_role أو مفتاح سري في الموقع؛ يستخدم فقط مفتاح publishable وصلاحيات جلسة المستخدم.

افتح الموقع، أنشئ حسابك، ثم يُمنح الحساب المختار صلاحية الإدارة من مالك مشروع سوبا بيس بعد تحديده وموافقته. لا تشارك كلمة السر. لا يكفي حساب لوحة Supabase نفسه للدخول؛ حساب Auth للتطبيق منفصل.

لتفعيل أول حساب إدارة، يُنفذ مالك المشروع بعد مراجعة البريد:
```sql
insert into public.x_admins(user_id)
select id from auth.users where email = 'البريد المختار'
on conflict(user_id) do nothing;
```
هذا يمنح إدارة كاملة؛ لا يُنفذ دون اختيار الحساب الصحيح. حسابات الموظفين داخل تطبيق التاجر لا تحصل صلاحية إدارة.

## تشغيل وبناء
```sh
npm ci
npm run build
npm test
```
المجلد dist هو الموقع الجاهز؛ ملفات src والكود البرمجي والدوال مرفقة. نسخة الموقع المنشورة خاصة بالمالك؛ إضافة أشخاص للموقع لا تمنح صلاحية Supabase.

## التحقق والحدود
نجح بناء JavaScript وفحص تركيب المصدر. نجحت اختبارات DOM محلية ببيانات اختبارية واختبارات PostgreSQL محلية لصلاحيات الإدارة والإشعارات والسجل. لا يمثل ذلك تجربة مالية أو تسجيل دخول إداري على المشروع الفعلي، إذ لم يُحدد حساب الإدارة بعد. لا بيانات تشغيلية وهمية ولا تحويل أموال تلقائيًا.
- إشعارات الخلفية تحتاج خدمة مستقلة، إرسال الإشعار هنا يحفظه داخل التطبيق.
- الموقع العام لصفحات الحجز يحتاج نشرًا منفصلًا.
- حذف التاجر نهائيًا وتوزيع صلاحيات جزئية بين موظفي الإدارة غير مضافين؛ الموجود حظر/رفع الحظر وإدارة كاملة للحسابات المخوّلة.
- سياسات الضمان والمحتوى التعليمي داخل تطبيق Flutter لم تتحول إلى محرر محتوى بهذه النسخة.
- غياب أداة معاينة محلية للمستخدم منع تسليم معاينة محلية؛ الموقع يُنشر على رابط فعلي.
- يلزم تحديث تطبيق Flutter إلى 2.0.2 لتلقي ترتيب/إخفاء الأقسام وروابط البنرات. لا APK مبني هنا.
